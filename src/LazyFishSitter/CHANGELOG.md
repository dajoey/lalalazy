# Changelog

## v0.1.3.0 (2026-09-05)

- Correction first, because the last release's notes got the game wrong: FFXIV does NOT force standing on every hooked fish. If the character is sitting when the cast starts, the game keeps it seated for the whole loop - a hook may cause a momentary stand, but the game sits back down on its own. v0.1.2.0 was designed around that mistake (one /sit per cast) and this release replaces it entirely.
- Sit once, then stay out of the way. The plugin now sends a single /sit per fishing trip, at a moment the game will actually accept it, and then does nothing for the rest of the trip (file: `FishSitService.cs`, `Decide`).
- That moment is the standby beat: rod out, no line in the water (`FishingEventHandler.State == PoleReady`), held for a second, at least 3 seconds clear of a bite/hook/reel, with the character read as standing for 3 seconds straight. It will never fire mid-cast, with a line in the water, mid-bite, mid-reel, or while already sitting down or standing up (file: `FishSitService.cs`, `IsStandbyBeat`).
- That is why v0.1.1.0 looked like it did nothing: it sent its one /sit the instant the fishing flag came on, which is after the line is already out, and the game swallows the emote there - ten sends across ten sessions, no effect. v0.1.2.0 still counted "line in water" as a valid moment and would have done the same thing.
- No re-sit after every cast, ever. A brief standing read just after a bite, hook, reel or collectable prompt is treated as the game's own animation, not as the character standing up, so the plugin does nothing and lets the game re-seat (file: `FishSitService.cs`, `IsHookish`).
- A "trip" is one visit to a fishing hole, not one cast. The fishing flag drops between casts (v0.1.1.0 saw ten "sessions" in 21 minutes), so the limits are now anchored to the hole and only reset after 20 seconds away from it (file: `FishSitService.cs`, `StartTrip` / `EndTrip`).
- Anti-yo-yo guards, all hard, because a /sit on a seated character STANDS them: never sends while any seated signal reads seated; at least 10 seconds between sends; at most 3 sends per trip with a log line when it stops; and once the game has taken a sit this trip it will not send again unless the seated read has proved it still reports seated with the rod out (file: `FishSitService.cs`, `Decide`, guards 1-5).
- The settings window now shows the trip counters: whether the character is at a hole, sits used out of 3, whether the game took the sit, and whether the seated read works while fishing (file: `ConfigWindow.cs`).
- Removed the "check interval" slider. The plugin now looks every frame, because every limit that matters is a real time limit (10 seconds between sends, 3 seconds of standing before it believes the read, 3 sends a trip) and a 2-second poll just made it step over short standby beats between quick casts. Saved values are ignored, not lost (files: `ConfigWindow.cs`, `Configuration.cs`).
- The policy is now a plain C# class with no game code in it (`Core/SitPolicy.cs`), replayed offline against 26 scripted fishing sessions by `tests/LazyFishSitter.Harness`. Three releases in a row shipped a rule that only broke in game; the harness caught three more before this one shipped, including a dead window that would have stopped a refused /sit from ever being retried.
- Keeps the detailed state logging (every fishing-state and posture change, 40 lines a minute max) and adds a one-line trip summary, so the still-open question - does the game ever report seated while a line is out - can be answered from the log without typing anything in game (file: `FishSitService.cs`, `EndTrip`).

## v0.1.2.0 (2026-09-05)

- SUPERSEDED BY v0.1.3.0 AND NEVER FISHED ON: the design premise below was wrong. It claimed the game forces standing on every hooked fish; it does not - if the character was sitting before the hook, the game re-seats automatically. Everything in this entry that follows from that premise (a /sit per stand episode) was removed in v0.1.3.0. Kept here for the record only.
- Re-sat after every cast and every catch, on the mistaken premise above: the unit was a "stand episode" (fishing start, or the fishing state machine passing through Hooking/ReleasingCatch/ConfirmingCollectable), and each episode got at most ONE /sit (file: `FishSitService.cs`, `Arm` / `TrackTransitions`).
- Sent only when it believed the game would accept it: read `EventFramework.Instance()->EventHandlerModule.FishingEventHandler` (FFXIVClientStructs) and required `State` to be `PoleReady` or `LineInWater` for at least 1 s with `ChangingPosition` false. Counting `LineInWater` as acceptable was the second defect - that is exactly where the emote gets swallowed (file: `FishSitService.cs`, `Tick`).
- Proof the sit took: `FishingEventHandler.ChangingPosition` going true within 3 s of the send was logged as `game accepted our sit`, with a 3 s outcome line per send. This part was correct and is kept in v0.1.3.0 (file: `FishSitService.cs`, `TrackTransitions`).
- No detector-driven re-arm: a "not seated" read after a sit never triggered a re-send on its own (that is what yo-yoed v0.1.0.0). Also kept in v0.1.3.0, hardened (file: `FishSitService.cs`, `Tick`).
- Logged every posture/fishing state CHANGE at Information, rate-limited to 40 lines/min: Fishing flag, FishingState, ChangingPosition, CanFish, Character.Mode/ModeParam, EmoteController.EmoteId, GetPosture(), and the combined SEATED verdict (file: `FishSitService.cs`, `TrackTransitions`, `LogTransition`).
- A failing FFXIVClientStructs signature (EventFramework or GetPosture) is logged once at Warning instead of being swallowed silently every check (file: `FishSitService.cs`, `Read`).
- Added the shared in-game "What's new" popup (repo standing rule): after an update this changelog opens once; `/lazyfishsitter changelog` reopens it (files: `Plugin.cs`, `Configuration.cs` `LastSeenChangelogVersion`, `LazyFishSitter.csproj` compiles `src/Shared/LalaChangelog`).

## v0.1.1.0 (2026-09-05)

- Fixed the sit/stand yo-yo: the seated check compared Character.Mode against raw bytes 12/13, which are RaceChocobo/TripleTriad in FFXIVClientStructs, so the player was never seen as seated and /sit was re-sent every check, and /sit while seated makes the character STAND (file: `FishSitService.cs`, `ReadPosture`; was `IsInPostureLoop`). Now compares against the `CharacterModes` enum (`EmoteLoop` = ground /sit, `InPositionLoop` = chair/bench/pose) - no raw bytes.
- Added a second, independent seated signal: the game's own `EmoteController.GetPosture()` (`SittingOnGround` / `SittingInChair`), so detection works even if Mode reads Gathering while a line is cast; either signal counts as seated (file: `FishSitService.cs`, `ReadPosture`).
- Belt and braces per fishing session: after one /sit has been sent, another is only sent once a posture read has confirmed the sit took AND the player has then read as not-seated on 2 consecutive checks; if the posture read never confirms, at most ONE /sit goes out per continuous Fishing session (re-arms when the Fishing condition drops). One bad read can no longer stand him up (file: `FishSitService.cs`, `Tick`).
- `/lazyfishsitter debug` now prints Mode (name + byte), ModeParam, EmoteController.EmoteId, the game posture, and the per-session counters so the seated-while-fishing question can be settled from the Dalamud log (file: `FishSitService.cs`, `LogDebugState`).

## v0.1.0.0 (2026-09-05)

- New plugin: while the game's Fishing condition is active, checks every few seconds (default 2) and runs /sit when the player is not already seated (file: `FishSitService.cs`, `Tick`).
- Seated detection reads the local Character's Mode field - 12 (EmoteLoop) covers persistent emotes like /sit, 13 (InPositionLoop) covers chair/bench and pose loops - the same read SimpleHeels' EmoteIdentifier uses, so the plugin never re-sits someone already seated, on a chair, or holding a pose (file: `FishSitService.cs`, `IsInPostureLoop`).
- The /sit is sent through the game's own chat-entry path (UIModule ProcessChatBoxEntry), inlined and trimmed from XivCommon's MIT Chat.cs - the same code ECommons ships inside this repo (file: `ChatCommand.cs`).
- Safety valves: never re-sends the sit command more than once per 3 seconds, and skips while between areas, in events, quest events, cutscenes, combat, mid-emote, or jumping (file: `FishSitService.cs`, `Tick`).
- Config: enabled toggle, check interval 1-10s, and the sit command itself (default /sit, must start with a slash) (files: `Configuration.cs`, `ConfigWindow.cs`).
- Ships on the TESTING channel first. Use /lazyfishsitter for settings, /lazyfishsitter debug for a state dump in the Dalamud log.
